# pdf-toc-splitter 仕様書

## リポジトリ情報

| 項目 | 内容 |
|------|------|

| Description | Split PDF files into chapters based on a table-of-contents Markdown file. |
| Visibility | Public |
| License | MIT |
| .gitignore | Python |

---

## 概要

目次（Table of Contents）の情報に基づき、PDFファイルを章・節単位で分割するCLIツール。
目次情報はMarkdownファイルとして外部から与える。目次Markdownの作成手段（人手・AI問わず）に依存しない汎用的な設計とする。

---

## スコープ

本プロジェクトに含めるもの：

1. **目次Markdownのフォーマット定義**
2. **目次PDF → 目次Markdown 生成を補助するプロンプトテンプレート**
3. **目次Markdownを入力としたPDF分割CLIスクリプト**

本プロジェクトに含めないもの：

- 分割後PDFのMarkdown化（別プロジェクトとする）
- PDF本体からの自動目次抽出（PDFブックマーク解析等）
- GUIの提供

## 1. 目次Markdownフォーマット定義

### 1.1 フォーマット仕様

ファイル名: `toc.md`（任意）

```markdown
# 書籍タイトルまたはPDFファイル名（任意。メタ情報として扱う）

<!-- offset: 4 -->

- 第1章 はじめに: 1-15
- 第2章 基本概念: 16-42
  - 2.1 定義: 16-25
  - 2.2 分類: 26-42
- 第3章 応用: 43-80
  - 3.1 ケーススタディ: 43-60
    - 3.1.1 事例A: 43-50
    - 3.1.2 事例B: 51-60
  - 3.2 まとめ: 61-80
- 付録A 用語集: 81-90
```

### 1.2 構文ルール

| ルール | 説明 |
|--------|------|
| リスト記法 | `-`（ハイフン）によるMarkdownリストを使用する |
| インデント | スペース2個で1階層。ネストは3階層まで許容 |
| 各行の形式 | `- {タイトル}: {開始ページ}-{終了ページ}` |
| ページ番号 | 印刷上のページ番号（目次に記載されている番号）をそのまま記述する。PDFの物理ページ番号への変換は `offset` で行う（1.3節参照） |
| タイトル | 1文字以上の文字列。空文字は不可。ファイル名に使用するためOS非許容文字は含めないことを推奨 |
| 見出し行 | `# ...` で始まる行はメタ情報として無視する（任意） |
| 空行 | 無視する |
| コメント | `<!-- ... -->` 形式のHTMLコメントは無視する（`offset` ディレクティブを除く） |

### 1.3 ページオフセット

多くのPDFでは、前付け（表紙、目次、まえがき等）の存在により、目次に印刷されたページ番号とPDFの物理ページ番号がずれる。このずれを `offset` ディレクティブで補正する。

#### 定義

```markdown
<!-- offset: N -->
```

`N` は整数。意味は「印刷ページ番号に `N` を加算すると物理ページ番号になる」。

#### 算出方法

1. PDFビューア（Adobe Reader等）で元PDFを開く
2. 本文の「1ページ目」（印刷上のページ番号が1のページ）に移動する
3. PDFビューアが表示する物理ページ番号を確認する
4. `offset = 物理ページ番号 − 1`

#### 例

表紙(物理1) → 目次(物理2-3) → まえがき(物理4) → 本文1ページ(物理5) の場合：
`offset = 5 − 1 = 4` → `<!-- offset: 4 -->`

目次上の「1ページ」は物理ページ `1 + 4 = 5` として分割される。

#### 省略時

`offset` ディレクティブがない場合は `offset: 0`（印刷ページ番号 = 物理ページ番号）として扱う。

#### CLIでの上書き

`--offset` オプションでも指定可能。CLIオプションが指定された場合はMarkdownファイル内の `offset` ディレクティブより優先する。

### 1.4 分割粒度の制御

分割は **最上位階層のみ** をデフォルトとする。
オプションにより任意の階層レベルまで分割可能とする。

例：上記の目次（offset: 4）で `--depth 1`（デフォルト）の場合、出力は以下の4ファイル：

```
01_第1章_はじめに_p5-19.pdf
02_第2章_基本概念_p20-46.pdf
03_第3章_応用_p47-84.pdf
04_付録A_用語集_p85-94.pdf
```

※ ファイル名中のページ番号は物理ページ番号（offset適用後）を使用する。

`--depth 2` の場合、子階層も個別ファイルとして出力する：

```
01_第1章_はじめに_p5-19.pdf
02_第2章_基本概念_p20-46.pdf
02-01_2.1_定義_p20-29.pdf
02-02_2.2_分類_p30-46.pdf
03_第3章_応用_p47-84.pdf
03-01_3.1_ケーススタディ_p47-64.pdf
03-02_3.2_まとめ_p65-84.pdf
04_付録A_用語集_p85-94.pdf
```

### 1.5 出力ファイル名の連番規則

#### 基本形式

```
{階層連番}_{タイトル}_p{物理開始ページ}-{物理終了ページ}.pdf
```

#### 階層連番の生成ルール

連番は深さ優先・出現順（＝目次の上から順）で付与する。各階層の連番はそれぞれ独立して1から採番し、`--prefix-digits` で指定された桁数で0埋めする。階層間はハイフン `-` で結合する。

| depth | 連番例 | 説明 |
|-------|--------|------|
| 1 | `01`, `02`, `03` | 最上位のみ |
| 2 | `01`, `02`, `02-01`, `02-02`, `03` | 親の後に子を出力 |
| 3 | `01`, `02`, `02-01`, `02-01-01`, `02-01-02`, `02-02`, `03` | 同様に再帰 |

#### prefix-digits の適用

`--prefix-digits`（デフォルト: 2）は **全階層共通** で適用する。

- `--prefix-digits 2`: `02-01`, `02-01-03`
- `--prefix-digits 3`: `002-001`, `002-001-003`

実装上、各階層の子エントリ数が `10^prefix-digits` を超える場合（例: prefix-digits=2 で子が100件以上）は桁あふれとなるが、エラーにはせず桁数を自動拡張する（例: `100`, `101`）。この挙動は警告ログを出力する。

#### タイトル部のサニタイズ

- 半角スペースは `_` に置換
- 全角スペースは `_` に置換
- OS非許容文字（`/\:*?"<>|`）は `_` に置換
- 先頭・末尾の `_` はトリミング
- 連続する `_` は1つに圧縮
- サニタイズ後のファイル名（連番＋タイトル＋ページ範囲の全体）が他エントリと重複した場合はバリデーションエラーとする

### 1.6 バリデーション

目次Markdownの読み込み時に以下を検証する。

#### エラー（処理中断）

| 検証項目 | 説明 |
|----------|------|
| フォーマット合致 | 各行が `- {タイトル}: {開始ページ}-{終了ページ}` に合致すること |
| タイトル非空 | タイトルが空文字でないこと |
| ページ番号正値 | 開始ページ・終了ページが1以上の整数であること |
| ページ範囲整合 | 開始ページ ≦ 終了ページ であること |
| 総ページ数以内 | offset適用後のページ範囲が元PDFの総ページ数を超えないこと |
| 子範囲が親範囲内 | 子エントリのページ範囲が親エントリのページ範囲に包含されること |
| インデント連続性 | インデントの飛び級がないこと（レベル1の次にレベル3は不可） |
| 深さ上限 | ネストが3階層を超えないこと |
| ページ範囲非重複 | 同一階層内でページ範囲が重複しないこと |
| ファイル名非重複 | サニタイズ後のファイル名が一意であること |

#### 警告（処理続行）

| 検証項目 | 説明 |
|----------|------|
| ページ範囲ギャップ | 同一階層内で連続するエントリ間にカバーされないページがある場合 |
| 連番桁あふれ | 子エントリ数が `10^prefix-digits` を超えた場合 |

## 2. プロンプトテンプレート

### 2.1 目的

目次ページのPDF（または画像）をAIに読み込ませ、セクション1のフォーマットに準拠した `toc.md` を生成させるためのプロンプトテンプレートを提供する。

### 2.2 ファイル

`prompts/toc_extraction_prompt.md` として配置する。

### 2.3 プロンプト要件

プロンプトには以下を含める：

- 出力フォーマットの仕様（セクション1の構文ルールを要約して埋め込む）
- ページ番号は目次に印刷されている番号をそのまま転記する旨の指示
- offset の算出手順と記述位置の説明（AIが元PDF全体を見ている場合は算出を試みるよう指示。目次ページのみの場合は `<!-- offset: TODO -->` と出力するよう指示）
- 目次に載っていない前付け・後付けは記載しない旨の指示
- 出力例（offset付きの完全な例）
- 「Markdownのコードブロックで出力せよ」等の出力制御指示
- 以下のあいまいケースの扱い指示

### 2.4 あいまいケースの扱い

プロンプトで以下のケースの対処を明示する：

| ケース | 指示 |
|--------|------|
| OCR誤読・判読不能な文字 | `[?]` で置き換え、`<!-- NOTE: ... -->` コメントで補足する |
| 判読不能なページ番号 | 開始・終了ともに `0-0` とし、`<!-- NOTE: ... -->` コメントで補足する。人間が後で修正する前提 |
| 複数行にまたがる見出し | 1行に結合してタイトルとする。改行位置に半角スペースを入れる |
| ドットリーダー（点線） | 無視する。タイトルとページ番号のみ抽出する |
| 目次に載っていない項目（前書き、奥付等） | 記載しない |
| ページ範囲が単一ページ | `N-N` と記述する（例: `- 序文: 1-1`） |

### 2.5 AI出力の暫定記法とバリデーションの関係

AI生成の `toc.md` にはセクション1のフォーマット仕様に準拠しない暫定記法が含まれる場合がある。具体的には以下の2つである：

- `<!-- offset: TODO -->` — AIがoffset値を算出できなかった場合
- `0-0` のページ範囲 — ページ番号が判読不能だった場合

これらはあくまでAI出力時の暫定記法であり、PDF分割スクリプト（セクション3）のバリデーションでは不正値として扱われる。人間が使用フロー（2.6節）のステップ5でこれらを修正してから分割スクリプトに渡すこと。

スプリッターは以下のように扱う：

| 暫定記法 | スプリッターの挙動 |
|----------|-------------------|
| `<!-- offset: TODO -->` | offset ディレクティブとして認識しない（通常のコメントとして無視される）。offset未指定として `0` が適用される |
| `0-0` のページ範囲 | ページ番号正値チェック（1以上）でバリデーションエラーとなる |

### 2.6 使用フロー

```
1. 人間がPDFビューアで元PDFを開き、offset を算出する
   （本文1ページ目の物理ページ番号 − 1）
2. 人間が元PDFから目次ページ部分だけを切り出し、独立したPDFにする
3. そのPDFをAI（Claude等）に読み込ませる際にこのプロンプトを併用する
4. AIが出力した toc.md に offset ディレクティブを記入する
   （AIが算出できない場合は人間が記入する。TODO のままでは分割不可）
5. toc.md を必要に応じて人間が微修正する
   （[?] の解消、0-0 ページの修正、タイトルの調整等。
    0-0 が残っているとバリデーションエラーになる）
6. toc.md をPDF分割スクリプトに渡す
```

## 3. PDF分割CLIスクリプト

### 3.1 技術スタック

| 項目 | 選定 |
|------|------|
| 言語 | Python 3.12+ |
| PDF操作 | pypdf |
| CLI | argparse（標準ライブラリ） |
| 依存管理 | pyproject.toml（既存リポジトリの構成に準拠） |
| テスト | pytest |

### 3.2 コマンド仕様

```bash
python -m pdf_toc_splitter <input.pdf> <toc.md> [options]
```

または pyproject.toml の `[project.scripts]` でエントリーポイントを定義し：

```bash
pdf-toc-splitter <input.pdf> <toc.md> [options]
```

#### 引数

| 引数 | 必須 | 説明 |
|------|------|------|
| `input.pdf` | 必須 | 分割対象のPDFファイルパス |
| `toc.md` | 必須 | 目次Markdownファイルパス |

#### オプション

| オプション | デフォルト | 説明 |
|-----------|----------|------|
| `-o`, `--output-dir` | `./output` | 出力ディレクトリ |
| `-d`, `--depth` | `1` | 分割する階層の深さ（1=最上位のみ、最大3） |
| `--offset` | なし | ページオフセット値。指定時はMarkdown内の `offset` ディレクティブより優先 |
| `--dry-run` | `false` | 分割を実行せず、生成されるファイル一覧を表示する |
| `--prefix-digits` | `2` | 連番の桁数（全階層共通） |
| `--validate-only` | `false` | 目次Markdownのバリデーションのみ実行する |

### 3.3 ディレクトリ構成

```

├── pyproject.toml
```

### 3.4 モジュール構成

#### `toc_parser.py`

- `TocEntry` データクラス: タイトル、開始ページ、終了ページ、階層レベル、子エントリのリスト、元ファイルの行番号を保持
- `parse_toc(filepath: str) -> tuple[list[TocEntry], int]`: 目次Markdownを解析し、ツリー構造のエントリリストとoffset値のタプルを返す
- `validate_toc(entries: list[TocEntry], total_pages: int, offset: int) -> tuple[list[str], list[str]]`: エラーメッセージのリストと警告メッセージのリストのタプルを返す
- `flatten_toc(entries: list[TocEntry], depth: int) -> list[TocEntry]`: 指定階層までフラット化する

#### `splitter.py`

- `generate_filename(entry: TocEntry, index_label: str, offset: int, prefix_digits: int) -> str`: エントリからサニタイズ済みファイル名を生成する
- `split_pdf(input_path: str, entries: list[TocEntry], output_dir: str, offset: int, prefix_digits: int) -> list[str]`: PDFを分割し、出力ファイルパスのリストを返す

#### `cli.py`

- `main()`: CLIエントリーポイント。引数解析 → パース → バリデーション → 分割の制御フロー

### 3.5 終了コード

| コード | 意味 |
|--------|------|
| 0 | 正常終了 |
| 1 | 入力ファイルエラー（PDF/目次が見つからない、PDFが読めない） |
| 2 | バリデーションエラー（目次の内容不正） |

### 3.6 エラーハンドリング

| エラー | 対処 |
|--------|------|
| 入力PDFが存在しない | エラーメッセージを表示し exit code 1 で終了 |
| 入力PDFが読めない（破損等） | エラーメッセージを表示し exit code 1 で終了 |
| 目次Markdownが存在しない | エラーメッセージを表示し exit code 1 で終了 |
| 目次Markdownにバリデーションエラー | パースエラー箇所を行番号付きで全件表示し exit code 2 で終了 |
| 出力ディレクトリが存在しない | 自動作成する |
| 出力ファイルが既に存在する | 上書きする（将来的に `--no-overwrite` オプション追加を検討） |

### 3.7 ログ出力

`print` による標準出力への進捗表示：

```

[INFO] Input PDF: example.pdf (94 pages)
[INFO] Output directory: ./output

[INFO]   1/4: 01_第1章_はじめに_p5-19.pdf (15 pages)
[INFO]   2/4: 02_第2章_基本概念_p20-46.pdf (27 pages)
[INFO]   3/4: 03_第3章_応用_p47-84.pdf (38 pages)
[INFO]   4/4: 04_付録A_用語集_p85-94.pdf (10 pages)

```

```
[WARN] Gap detected: pages 34-36 not covered between entries at depth 1
```

## 4. テスト方針

テストフレームワーク: `pytest`

### 4.1 toc_parser のテスト（`src/tests/test_toc_parser.py`）

#### 正常系

- 単階層の目次パース
- 複数階層（depth 2, 3）の目次パース
- 空行・HTMLコメント含みの目次パース
- offset ディレクティブの読み取り（あり・なし・0指定）
- 単一ページエントリ（`5-5`）

#### 異常系（バリデーションエラー）

- フォーマット不正の行（コロンなし、ページ番号なし等）
- タイトル空文字
- ページ番号が0以下
- 開始ページ > 終了ページ
- ページ範囲がPDF総ページ数を超過
- 子エントリの範囲が親範囲を超過
- インデント飛び級（レベル1→レベル3）
- ネスト4階層以上
- 同一階層でのページ範囲重複
- サニタイズ後のファイル名重複

#### 警告系

- 同一階層のエントリ間にページギャップがある場合

### 4.2 splitter のテスト（`src/tests/test_splitter.py`）

テスト用PDFは `pypdf` で動的に生成する（各ページにページ番号テキストを埋め込む）。

#### 分割機能

- depth 1 での分割と出力ファイル数・ページ数の検証
- depth 2 での分割と出力ファイル順序（深さ優先）の検証
- depth 3 での分割
- offset 適用後のページ抽出が正しいことの検証

#### ファイル名生成

- 基本的なファイル名生成
- OS非許容文字のサニタイズ
- 全角スペース・連続スペースの処理
- prefix-digits 指定（2桁、3桁）
- 桁あふれ時の自動拡張

#### CLIオプション

- `--dry-run`: ファイルが生成されず、一覧が標準出力に出ること
- `--validate-only`: バリデーションのみ実行され、PDFが生成されないこと
- `--offset`: Markdown内 offset より CLI 指定が優先されること
- `--depth` の範囲外指定（0, 4以上）のエラーハンドリング

#### 終了コード

- 正常終了時に exit code 0
- 存在しないPDF指定時に exit code 1
- バリデーションエラー時に exit code 2

#### エッジケース

- 出力先に同名ファイルが既存の場合の上書き確認
- 出力ディレクトリの自動作成
