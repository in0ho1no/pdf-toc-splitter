# 目次抽出プロンプトテンプレート

このファイルは、PDFの目次ページをAIに読み込ませて `toc.md` を生成させるためのプロンプトテンプレートです。
以下の「--- プロンプト開始 ---」から「--- プロンプト終了 ---」の間をコピーしてAIへの指示として使用してください。

---

--- プロンプト開始 ---

この指示は、PDFファイルを直接添付できる場合は添付PDFを対象に、添付できない場合は別途貼り付けられた目次テキストを対象に適用してください。

添付したPDFの目次ページを読み取り、以下のフォーマットに従った目次Markdownを生成してください。

## 出力フォーマット

```
# 書籍タイトルまたはPDFファイル名（任意）

<!-- offset: N -->

- 章・節タイトル: 開始ページ-終了ページ
  - サブセクションタイトル: 開始ページ-終了ページ
    - サブサブセクションタイトル: 開始ページ-終了ページ
```

### 構文ルール

- リストのマーカーは `-`（ハイフン）を使用する
- インデントはスペース2個で1階層。ネストは3階層まで
- 各行の形式: `- {タイトル}: {開始ページ}-{終了ページ}`
- ページ番号は目次に印刷されている番号をそのまま転記する（PDFビューアの物理ページ番号ではない）
- タイトルは空文字にしない
- 見出し行（`# ...`）はメタ情報として1行目に任意で記載可

## offsetディレクティブ

多くのPDFでは前付け（表紙・目次・まえがき等）により、目次に印刷されたページ番号とPDFの物理ページ番号がずれる。
このずれを `<!-- offset: N -->` ディレクティブで補正する。`N` は整数。

### offsetの算出方法

1. 元PDFをPDFビューアで開く
2. 本文の「1ページ目」（印刷上のページ番号が1のページ）に移動する
3. PDFビューアが表示する物理ページ番号を確認する
4. `offset = 物理ページ番号 − 1`

**例:** 表紙(物理1) → 目次(物理2-3) → まえがき(物理4) → 本文1ページ(物理5) の場合:
`offset = 5 − 1 = 4` → `<!-- offset: 4 -->`

### offsetが算出できない場合

元PDF全体を参照できる場合はoffsetの算出を試みること。
目次ページのみを参照しており本文の物理ページ位置が不明な場合、または目次テキストだけが渡されていて物理ページ位置が分からない場合は `<!-- offset: TODO -->` と記述すること。
人間が後で整数値に修正する。

## 記載しない項目

以下の項目は目次に記載されていても含めない:

- 前付け（表紙、目次ページ自体、まえがき、はじめに等）
- 後付け（奥付、広告等）
- 目次ページに記載されていない項目

## あいまいケースの対処

| ケース | 対処方法 |
|--------|---------|
| OCR誤読・判読不能な文字 | `[?]` で置き換え、直後に `<!-- NOTE: 判読不能のため仮置き -->` コメントを追記 |
| 判読不能なページ番号 | 開始・終了ともに `0-0` とし、直後に `<!-- NOTE: ページ番号判読不能 -->` コメントを追記 |
| 複数行にまたがる見出し | 1行に結合してタイトルとする。改行位置に半角スペースを挿入 |
| ドットリーダー（点線）やスペーサー | 無視する。タイトルとページ番号のみ抽出する |
| ページ範囲が単一ページ | `N-N` と記述する（例: `- 序文: 1-1`） |
| 目次に載っていない前書き・奥付等 | 記載しない |

## 暫定記法の説明

AI生成の `toc.md` には以下の暫定記法が含まれる場合がある。これらは構文上は許容されるが、実際のPDF分割前に人間が修正する必要がある。

| 暫定記法 | 意味 | 対処 |
|----------|------|------|
| `<!-- offset: TODO -->` | offsetが算出できなかった | 整数値に修正する |
| `0-0` のページ範囲 | ページ番号が判読不能だった | 正しいページ番号に修正する |

## 出力例

以下のような形式でMarkdownコードブロックとして出力すること:

~~~markdown
# サンプル技術書

<!-- offset: 4 -->

- 第1章 はじめに: 1-15
- 第2章 基本概念: 16-42
  - 2.1 定義: 16-25
  - 2.2 分類: 26-42
- 第3章 応用: 43-80
  - 3.1 ケーススタディ: 43-60
    - 3.1.1 事例A: 43-50
    - 3.1.2 事例B: 51-60
  - 3.2 まとめ: 61-80
- 付録A 用語集: 81-90
~~~

## 出力の制約

- 出力はMarkdownのコードブロック（` ```markdown ` で囲む）で行うこと
- コードブロックの外に説明文を添える場合は、コードブロックの後にまとめて記載すること
- 目次の内容のみを出力し、余分な整形や要約を加えないこと

--- プロンプト終了 ---

---

## 使用フロー

```
1. 人間がPDFビューアで元PDFを開き、offsetを算出する
   （本文1ページ目の物理ページ番号 − 1）
2. 人間が元PDFから目次ページ部分だけを切り出し、独立したPDFにする
3. そのPDFをAI（Claude等）に読み込ませる際にこのプロンプトを併用する
  （PDF添付できない場合は、目次テキストを貼り付けて同じプロンプトを使う）
4. AIが出力した toc.md に offset ディレクティブを記入する
   （AIが算出できない場合は人間が記入する）
5. toc.md を必要に応じて人間が微修正する
   （[?] の解消、0-0 ページの修正、タイトルの調整等）
6. toc.md をPDF分割スクリプトに渡す
```
